# MCF peer discovery and Buds context: static findings

Scope: SamsungContinuityService 2.1.11.0 `WindowsMCFCore` dependency assemblies; offline CIL only. No target execution, credential-store inspection, user database access, or Linux-worker edits. SHA-256 identities are in `peers-artifacts.json`; REA metadata summaries and limits in `peers-rea-metadata.json`. IL was generated by installed `ikdasm`, successful exit for all five artifacts.

## Answered

1. **Galaxy Connect's Auto Switch tile delegates to Samsung Settings.** `ContinuityFeatureApps.FeatureApps.AutoSwitchBuds::.ctor` loads the SamsungSettings package family and `samsungsettings15:-Go-AutoSwitchBudsDetail`; `LaunchApp` calls `AppBase.Launch` (`peers-ContinuityFeatureApps.dll.il:1577–1608`). This class supplies no Buds Bluetooth implementation. High confidence, observed instructions. Metadata parent evidence `ev_20a27ef385b9317b1d2e7f22fb38f1583d75b03fcab69cbebd340d5ca0b5e1e2`.

2. **MCF has Buds-related peer context beyond the existing SMEP RFCOMM session.** `MCFCommons.Models.LTV.DataType` defines `AS_DEVICE=3` (`peers-Commons.dll.il:44482`), and `ASDeviceData.ParseData` decodes the first byte as `MACAddressLastByte`, second as `MACAddressByteXOR`, third as state, then extra data (`:42085–42245`). `LTVHandlerImpl.SetLTVData` stores this object per discovered device (`:45430` approximately; exact method spans :45294–45594). This is a compact identifier and state record, not a full MAC address, key, or proof of ownership.

   State masks, verified against both ParseData and ASDeviceStateData.ConvertStateToInt (:48452): HFP_CONNECTED=0x80, HFP_ACTIVE=0x40, A2DP_CONNECTED=0x20, BUDS_IN_EAR=0x04, BUDS_SPP_CONNECTABLE=0x02. Extra byte: WATCH_SUPPORTED bit0, SEQUENCE bits1–3, VOLUME upper four bits; optional next byte RELAY_CALL_SUPPORTED bit7. `ASDeviceData.GenerateData` constructs these bytes (:42247–42334), so these are implemented fields rather than names alone. High confidence for encoding; Main-executable search finds ASDeviceData construction only in generic LTV parser (`WindowsMCFCore.il:251228`), with no direct AutoSwitchSettings/BUDS_SPP_CONNECTABLE/A2DP_CONNECTED getters. Generic storage/forwarding is possible, but an active Buds decision consumer was not established.

3. **Base BLE context schema contains an Auto Switch settings bit; this PC sender leaves it clear.** `BaseContextData.ParseData` (:42777–42932) optionally consumes a five-byte account identifier when data length >6, then two-byte CoC channel, device state, network state and feature byte; low-nibble feature bits give ContinuitySettings bit0, AutoSwitchSettings bit1, BTConnectionType bit2 (:42870–42897). `GenerateData` serializes the context (:42935–43058). However, main-executable `StaticLtvDataManager.GetBaseContextData` (`WindowsMCFCore.il:243701–243784`) constructs `[0,0,10,network,4|continuitySettings]` plus optional BSSID. Thus BTConnectionType bit2 is set, AutoSwitchSettings bit1 is clear in this sender. The schema alone does not establish PC Buds advertisement.

4. **Samsung BLE framing has explicit identity and one-to-many markers.** `MCFCommons.Constants.Discovery.BleConst` (:83274–83367) defines company ID0x0075, Samsung version2, service0x18, PC type5, ONE_TO_N_SUPPORT_VERSION3. Extended headers have an eight-byte account hash at offset5; legacy base context declares five-byte account ID. Family packet flag0x40 and extended flag0x80 exist. These are declaration observations; do not equate ONE_TO_N_SUPPORT_VERSION3 with SMEP MDEv3 or with a three-device connection count.

5. **Discovery registry itself does not evict an old peer to add a new peer.** Full body of `DiscoveredDeviceManager.AddDevice` (:78912–78987) validates MAC, checks dictionary membership, inserts new device and two ID mappings, then returns it. No count comparison or eviction call is in that method. `RemoveDevice` (:78989–79079) removes the specified MAC, not the oldest peer. The registry supports collections of devices, but this says nothing about Buds firmware's active ACL/profile limit. High confidence bounded negative on this method only.

6. **An AUTOSWITCHING event ID is not itself an implemented policy.** EventCxtHandlerId defines AUTOSWITCHING=1 (:47965). HandlerFactory.CreateHandlerFromByteData (:46987–47056) specializes only IDs2,3,13 and wraps others in BaseHandler. Do not interpret this enum as evidence that Galaxy Connect's MCF service itself implements takeover logic.

7. **ServiceCommons is logging contracts only in this build.** The 4KB DLL has one interface with three methods (metadata complete); it contains no connection policy. ProtoMessage.AuthCommand is generated protobuf with fields command1,result2,address3,nonce4,hash5,repeated channel6,supportTcpKeep7,scpmRevisionNumber8,memberId9 (`peers-ProtoMessage.dll.il:243–266`). Authentication and same-account trust semantics belong to callers in the main executable; schema alone proves no security protocol.

## Unresolved

No explicit maximum simultaneously connected Buds hosts or eviction rule was established from these five assemblies. Bounded textual searches included buds/seamless/multipoint/autoswitch and device maximum/count/limit terms; full method tracing concentrated on the registry and LTV encoders, not every Commons method. Missing Windows-native BLE advertisement, same-account filtering and consumer-side behavior remain root main-executable work. Firmware may enforce limits invisible to this host code. No runtime or four-device compatibility claim follows from this analysis.
